# INDIGO OPS // Airline Operations Control System

A local, terminal-styled airline back-office operations **prototype/simulation**,
inspired by IndiGo's operational workflow. No login, no real airline systems,
mock data only — this is not an official IndiGo product.

Covers the full passenger/flight lifecycle end to end with a real relational
database and business-rule enforcement:

```
FLIGHT CREATE → AIRCRAFT/GATE ASSIGN → BOOKING (PNR) → CHECK-IN → SEAT
  → BAGGAGE + EXCESS BAGGAGE CHARGE → MEAL VOUCHER → LOUNGE PASS
  → BOARDING PASS → BOARDING → GATE CLOSE → DEPARTURE CHECKLIST → DEPARTED
  → LANDED → DISEMBARKATION → BAGGAGE RECONCILIATION → FLIGHT CLOSURE
```

## Stack

- **Backend**: Node.js, Express, TypeScript, Prisma ORM, SQLite
- **Frontend**: React, TypeScript, Vite, Tailwind CSS
- QR codes generated locally (`qrcode` package); barcodes rendered as inline SVG

## Run it

```bash
npm install
npm run db:push   # create the SQLite schema
npm run seed      # load mock flights/passengers/bookings
npm run dev       # starts API on :4000 and UI on :5173
```

Open http://localhost:5173

## Structure

- `server/` — Express API, Prisma schema (`prisma/schema.prisma`), seed script,
  and business-rule services (`src/services/*`)
- `client/` — React terminal UI: dashboard, flight ops console, check-in/PNR
  workspace, baggage, boarding, gates, reports, audit log, command terminal
  (`Ctrl+K`), global search (`/`)

## Keyboard shortcuts

`F1`–`F8` module navigation · `/` global search · `Ctrl+K` command terminal
(`OPS>` prompt — try `HELP`, `PNR SEARCH <PNR>`, `FLIGHT STATUS <NUM>`,
`VERIFY <payload>`) · `Esc` close modal

## Notes

- All passenger/flight data is fictional, generated by `server/prisma/seed.ts`.
- Business rules (check-in closure, boarding prerequisites, gate conflicts,
  departure checklist, baggage/passenger reconciliation, etc.) are enforced
  server-side and surfaced as terminal-style `ERROR [OPS-xxx]` responses.
